# Network services and troubleshooting

The wallet signs on the user's device or paired signer. Reading a balance or history sends a public address to the selected node or indexer. Broadcasting sends the signed transaction, including its public transaction data. A provider can associate multiple requests from the same client. The seed phrase and account private keys are unnecessary for these requests. Some Superhero services also receive message signatures the wallet makes automatically (see notifications below).

## Chain data and fees

| Service | What it receives and supplies | What to check |
| --- | --- | --- |
| æternity node | Account and contract queries, network ID, fee/gas queries and signed transactions. The SDK uses the active network's `nodeUrl`. | If the node is unavailable, the wallet cannot read current state or submit a transfer there. Verify the node URL and reported network ID. [Network defaults](../src/protocols/aeternity/config.ts) |
| æternity middleware | Addresses, names, transaction hashes and contract IDs for indexed history, AENS and AEX-9 data. | If a transaction appears at the node but history is stale, check the middleware's `/v3/status` on the same network. The wallet flags an unsynced middleware more than five blocks behind. [Middleware](../src/protocols/aeternity/composables/aeMiddleware.ts) · [Status messages](../src/composables/connectionStatus.ts) |
| EVM RPC | Ethereum, BNB, Polygon PoS and Avalanche C-Chain nodes receive address queries, calls for fee estimation (including sender, recipient and call data), and signed transactions. | Verify the protocol, chain ID and RPC URL when gas estimation or broadcast fails. A working RPC can still return a balance when the separate history indexer is down. [EVM network selection](../src/protocols/evm/helpers/activeEvmNetworkSettings.ts) |
| Etherscan-compatible indexers | Etherscan V2 for Ethereum, BNB and Polygon, and Snowtrace for Avalanche. Account, chain and token identifiers are used to find transaction history. | If native balances update but history is empty, check the indexer's network coverage, quota and `ETHERSCAN_API_KEY`. [Indexer client](../src/protocols/ethereum/libs/EtherscanService.ts) |
| EVM token services | Ethplorer on Ethereum, Binplorer on BNB mainnet, and Alchemy on BNB testnet and Polygon fetch token balances or metadata using owner and contract addresses. | The token list can be incomplete when a service is unavailable or throttled. Ethplorer uses a shared `freekey` when `ETHPLORER_API_KEY` is empty. Alchemy endpoints use `ALCHEMY_API_KEY`. Avalanche has no default token indexer. [Ethplorer](../src/protocols/ethereum/libs/EthplorerService.ts) · [Alchemy](../src/protocols/evm/libs/AlchemyService.ts) · [Avalanche configuration](../src/protocols/avalanche/config.ts) |
| Bitcoin and Dogecoin REST APIs | The wallet looks up addresses, unspent outputs, previous transactions and fee estimates, and posts the raw signed transaction. Bitcoin defaults to Blockstream. | These adapters require Esplora-style paths such as `/address/{address}/utxo` and `POST /tx`. The Dogecoin mainnet default points at retired SoChain v2. A compatible Dogecoin endpoint is needed for discovery, balance and broadcast. [Bitcoin configuration](../src/protocols/bitcoin/config.ts) · [Dogecoin adapter](../src/protocols/dogecoin/libs/DogecoinAdapter.ts) |
| Solana RPC and token list | The default Alchemy RPC receives public keys, mint or token account queries, fee queries and signed transactions. The wallet downloads a public mint list from GitHub for mainnet token names and symbols. | Check the Solana `nodeUrl` and Alchemy key if balance or submission fails. Devnet skips the mainnet list. The adapter can read mint decimals over RPC when metadata is missing. [Solana configuration](../src/protocols/solana/config.ts) · [Token metadata lookup](../src/protocols/solana/libs/SolanaAdapter.ts) |

## Prices, dApps and Superhero services

| Service | Data and purpose | Effect of an outage or missing configuration |
| --- | --- | --- |
| CoinGecko | Coin IDs and fiat currency codes for exchange rates and market data. | Cached prices can remain on screen. Use the chain balance and transaction hash when investigating a payment. [Price requests](../src/lib/CoinGecko.ts) |
| WalletConnect / Reown | WalletKit uses a relay connection and a build-time project ID. At pairing, the dApp receives every wallet account for the requested chains. After an account or network switch, the session lists every EVM account on every configured chain. The dApp can send requests through the session. Once WalletConnect starts, its SDK also reports a client ID, user agent and pairing errors to Reown's telemetry endpoint. | An empty `WALLET_CONNECT_PROJECT_ID` prevents initialization. Check the project ID, relay connectivity and presence of an account for the requested EVM chain. [WalletConnect setup](../src/composables/walletConnect.ts) |
| Superhero tipping and notifications backend | Tip claims send the tipped URL and claimant address. While the wallet is open, it sends the active æternity seed account's address to the network's `backendUrl` every 30 seconds and signs the backend's challenge message with that account without a prompt. On a custom network, set `backendUrl` only to a backend you trust. | Claims or notifications can fail independently of an AE transfer. Check the active network's `backendUrl`. [Tip claims](../src/protocols/aeternity/composables/aeTippingBackend.ts) · [Notifications](../src/composables/notifications.ts) |
| æternity multisig backend | Every æternity address in the wallet, about once a minute while the wallet is open, to find vaults that list it as a signer. A proposal sends its transaction, authentication hash and gas parameters. Co-signers retrieve the transaction by hash. | An on-chain proposal may be visible while its transaction details are unavailable. Check the multisig service for that network before asking co-signers to approve. [Vault discovery](../src/composables/multisigAccounts.ts) · [Proposal storage](../src/composables/multisigTransactions.ts) |
| Superhero address-link API | Account address, preferred `.chain` name and signed challenge. The service verifies ownership and pays to submit the link. | A failure can stop the preferred-name update. Check the network's `superheroApiUrl`. [Address-link client](../src/protocols/aeternity/composables/aeAddressLinkBackend.ts) |
| æternity token-sale APIs | Account and contract addresses (every æternity address in the wallet, sent to the default and to each added API) to discover sale tokens, factories and sale metadata, including price. | Check `TOKEN_SALES_URL_MAINNET` or `TOKEN_SALES_URL_TESTNET` in a local build. Additional API URLs can be set per network under **Wallet settings → Token sales**. [Sale discovery](../src/protocols/aeternity/composables/aeTokenSales.ts) |

Opening a transaction in an explorer shares its hash with that site. The testnet faucet link includes the selected æternity address. Opening Superhero DEX navigates to a separate dApp, where a wallet connection can be requested. [Faucet link](../src/protocols/aeternity/helpers/index.ts) · [Wallet links](../src/popup/pages/More.vue)

## Custom networks and local builds

Under **More → Wallet settings → Network**, add a named network and check the fields for each chain you intend to use. Saving selects the new network. Use RPC, middleware and explorer URLs for the same chain. Some supporting services are predefined by network type. For example, custom Ethereum networks use the testnet indexer settings, and custom æternity networks use the testnet multisig and address-link defaults. Changing a node alone can therefore leave history or service-backed features unavailable or showing testnet data. Bitcoin accounts on a custom network use testnet derivation and `tb1…` addresses, so don't share them for mainnet payments. [Network form](../src/popup/pages/NetworkForm.vue) · [Ethereum service selection](../src/protocols/ethereum/composables/ethNetworkSettings.ts) · [æternity service selection](../src/protocols/aeternity/composables/aeNetworkSettings.ts)

Set build-time API keys, the WalletConnect project ID and token-sale URLs in the build environment or a local Vite environment file, then restart the dev server or rebuild. These values are compiled into distributed clients. Use provider credentials intended for client applications. [Build definitions](../build/env.ts) · [Vite environment loading](../vite.config.mts)

## Reporting a problem

Include the wallet version, platform, active chain/network, affected feature and error message. A public transaction hash is useful if you choose to share it. Turn on **Keep error log** under **Wallet settings → Error log** before reproducing the problem; earlier errors are not saved. The export contains error details, wallet version, browser/platform and timestamps. Review the exported file for private URLs, credentials, pairing or unclaimed gift card links, and addresses you wish to keep private. Keep seed phrases and private keys out of reports. The support guide lists both the bug form and the private security contact. [Error log](../src/lib/logger.ts) · [Support and security disclosure](https://developer.superhero.com/resources/support/)
